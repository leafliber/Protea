# ADR-0008：历史只追加，容量以交接处理

状态：Accepted · 日期：2026-11-03 · 相关：[../10-architecture/05-sessions-and-agent-loop.md](../10-architecture/05-sessions-and-agent-loop.md) · [../10-architecture/06-context-assembly.md](../10-architecture/06-context-assembly.md)

## 背景

两个约束同时指向同一方向：（1）Claude 5 系列的"保留思考"要求思考块原样回传，且编辑早先回合会使后续思考块失效（新账户返回 400）；（2）提示缓存是前缀匹配，改写历史会让缓存失效。Cortico 的做法是交接（handoff）：人格决定保留的尾部与笔记，Core 重置会话。

## 决策

- 会话转录**只追加**；启动修复只追加标记，不改写既有行。
- 容量管理采用 **交接**：生成交接笔记（记忆文件）→ 重建前缀 → 新转录文件带尾部 → 旧文件封存。
- 可选地在交接前使用 Provider 的服务端压缩（Anthropic `compact` beta），但其输出的 compaction 块必须原样回传，且压缩不改变"只追加"的本地记录。
- 上下文编辑（清除旧工具结果）只对 Fork 默认启用；主会话需实测缓存影响后决定。

## 备选方案

- 客户端滚动窗口（删除最早消息）：违反保留思考约束，且破坏缓存。
- 完全依赖服务端压缩：Provider 锁定；不支持的 Provider 无兜底。

## 后果

- 每次交接会产生一次缓存冷启动；通过把交接做成"低频大动作"来摊销。
- 交接笔记质量决定长期一致性；需要评测集（回放）持续检验。
