# ADR-0011：分层记忆、闲时压缩与每日整理

状态：Accepted · 日期：2026-11-10 · 相关：[../10-architecture/11-memory-and-persona.md](../10-architecture/11-memory-and-persona.md) · [../10-architecture/05-sessions-and-agent-loop.md](../10-architecture/05-sessions-and-agent-loop.md) §8 · [../10-architecture/06-context-assembly.md](../10-architecture/06-context-assembly.md) §7 · [ADR-0008](ADR-0008-append-only-history-and-handoff.md)

## 背景

M4 的记忆有几个问题：压缩只在上下文快满时发生，往往正赶上主人在等回复；交接后模型要自己读文件才知道之前在做什么；`INDEX.md` 一改就让整段对话的缓存失效；目标和待办没有结构化的位置；检索对日志和笔记一视同仁，中文两字词没有相关度排序；记忆整理靠模型自觉，几乎不发生。

主人的要求：服务单一对话；闲时自动压缩；长期记忆分层检索；保留原文供审查但一般不召回；有自动整理；不引入 embedding；有可被工具更新的目标、待办、注意事项；上下文要短；兼顾各厂商的前缀缓存。

## 决策

- **四层**：白板（结构化，数据库）→ 索引（`INDEX.md`，常驻前缀）→ 笔记（`notes/`，按需）→ 原文（`journal/`、`handoff/`、`raw/`、转录，默认不召回）。
- **闲时压缩是常态，容量交接是兜底**，两者共用 ADR-0008 的交接流程。低水位 32k（只算对话）、上限 80k、保留尾部 8k。优先等 Provider 缓存过期，此时压缩只多花一次笔记请求。
- **一份笔记直接进新对话**，放在单独的块里，不放进 `internal` 事件（P4）。
- **压缩时另存可读原文**，写入前脱敏，不进 Git 备份。
- **白板不进前缀**，也不做临时注入。写操作只回一行收据；别的来源改过时在下一批带上完整白板，都写入转录。
- **检索不用 embedding**：FTS5 + CJK 重叠二元组 + 摘要与关键词加权 + 默认只查笔记。
- **`INDEX.md` 延迟发布**：只在压缩、梦境结束、主人修改、启动时生效。其他分段行为不变。
- **每日梦境**：Core 只决定何时运行并记录结果，流程写在 Skill 里；工具白名单决定了它联系不到任何人。

## 备选方案

- 向量检索（sqlite-vec + embedding 模型）：多一个模型依赖和一套索引，主人明确不要。字面检索的短板由关键词、索引摘要和模型改写查询弥补；实测不够再议。
- 白板放进系统前缀，或每批注入：前者每改一次都让缓存失效，后者让历史持续膨胀。
- 请求时临时注入、不落转录：只发一次的内容会破坏 Claude 5 的 thinking 块前缀绑定。
- 批开始时自动召回相关笔记：要 Core 判断相关性（违反 P1），每批都往历史里塞内容。
- 短摘要与完整笔记两份：多一层解析，原文层已经保证了完整性。
- 所有前缀分段都延迟生效：人格文件只在主人编辑时变化，延迟只会让主人困惑。

## 后果

- 常态上下文约 48k 以内，压缩多发生在主人感觉不到的时候。
- 摘要与整理的质量决定长期一致性，只能用真实模型实测（T3、T11）。
- 字面检索对完全换了说法的问题召回较弱。
- 已部署实例的 `OPERATING.md` 是首次启动时复制的，不会自动更新，升级时要手动替换。
