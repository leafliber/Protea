# ADR-0002：事件日志作为唯一事实源

状态：Accepted · 日期：2026-11-03 · 相关：[../10-architecture/03-event-store-and-bus.md](../10-architecture/03-event-store-and-bus.md)

## 背景

常驻代理需要在重启、崩溃、升级后恢复到一致状态；调试需要复现时序；审计需要追溯副作用的起因。

## 决策

所有输入（事件）、投递结果、审批、用量、审计都以 **append-only 记录**持久化到 Event Store；运行时状态（pending 队列、会话阶段、预算余量）是这些记录的**投影**，可以从记录重建。会话转录同样只追加。

规则：

- 删除只发生在保留期清理，且先追加 `purge` 记录。
- 撤回是追加 `withdrawn` 记录，不是删除事件。
- 游标不复用。

## 备选方案

- **可变状态表 + 事件日志作为副产品**：实现简单，但恢复逻辑会出现两套真相。
- **外部消息队列（NATS JetStream、Redis Streams）**：多进程/多实例时更合适，但违背单镜像、零依赖目标。

## 后果

- 启动恢复 = 转录修复 + 以转录为准对账非终结事件 + 按游标继续投递 pending 事件。
- 存储增长线性；需要保留期策略。
- 所有调度决策必须被记录（作为 `internal` 事件或 `batches` 表），否则投影不完整。
