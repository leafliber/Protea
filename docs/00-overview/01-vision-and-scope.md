# 愿景与范围

> 状态：Draft · 更新：2026-11-03

## 一句话

Protea 是一个 **常驻在云端、以事件流为心跳、能力可热插拔** 的个人助理运行时（harness）。它不是一个聊天机器人框架，而是一个"一直醒着"的代理内核：世界的变化以事件形式流入，助理在合适的时机决定做什么、说什么，或者什么都不做。

## 我们要解决的问题

传统的"请求—响应"聊天助理只有在被问到时才存在。一个真正的个人助理需要：

1. **常驻**：24/7 运行，重启后不丢记忆、不丢未处理的事件。
2. **多源混合输入**：聊天消息、定时提醒、邮件、日历、Webhook、RSS、文件变化……来自不同渠道，节奏不同、重要性不同。
3. **有轻重缓急**：主人发来的消息必须立刻响应，哪怕助理正在做一份后台周报；RSS 的一条更新则可以攒一批再看。
4. **能力随需扩展**：接入新的 MCP 服务器、加一个 Skill、换一个渠道，不需要重启、不需要改内核。
5. **自己能跑**：一个 Docker 镜像、一个数据卷，在任意 VPS 上起来。

## 目标（In Scope）

| # | 目标 | 可验证的标准 |
|---|---|---|
| G1 | 事件流驱动的常驻内核 | 进程生命周期内持续消费事件；重启后从上次游标继续，未投递事件不丢失 |
| G2 | 事件源插件 + 处理等级 + 抢占 | 插件声明等级 L0–L4；L1 事件在 ≤1s 内打断 L3 后台回合并得到响应 |
| G3 | 热插拔 | 不重启主进程即可安装/启用/禁用/重载/卸载插件、MCP 服务器、Skill |
| G4 | MCP 支持 | 支持 stdio 与 Streamable HTTP 传输；工具/资源/提示词进入模型能力面 |
| G5 | Skills 支持 | 兼容 Agent Skills 的 `SKILL.md` 格式；渐进式披露；目录热加载 |
| G6 | 单镜像部署 | `docker run -v protea-data:/data ghcr.io/.../protea` 即可运行，含控制台 |
| G7 | 可观测与可控 | 结构化日志、指标端点、事件流实时查看、审批与预算控制 |
| G8 | 安全默认 | 只有主人可指挥；危险工具默认需审批；秘密不进上下文 |

## 非目标（Out of Scope，至少 v1 不做）

- **多租户 / 多用户 SaaS**：Protea 服务于一个主人（owner），一个部署一个助理。
- **通用工作流编排引擎**：不做 DAG 编排器；复杂流程由模型 + 工具 + Fork 完成。
- **自研模型推理**：只对接外部模型 API；不内置本地推理（可通过 Provider 插件接入）。
- **移动端 / 富客户端**：渠道交互依赖现有平台（Telegram、Slack 等）；自带控制台只用于运维。
- **预设人格或记忆方案的"产品化"**：内核对人格与记忆内容保持无语义，只提供布局与工具。
- **水平扩展 / 集群**：单实例即可；高可用通过快速重启与数据卷备份实现。

## 典型场景

1. **即时对话**：主人在 Telegram 发"帮我看看明天日程并提醒我 8 点出门"。L1 事件立即唤醒主会话；助理调用日历 MCP 工具、创建定时事件源的一次性提醒。
2. **后台巡检被打断**：每天 07:00 的 L3 定时事件触发"晨报"Fork，正在抓取 5 个 RSS 源；此时主人发来消息（L1）。主会话立即处理主人消息；Fork 在下一个回合边界被降速或暂停，之后恢复。
3. **自主关注**：GitHub Webhook（L2）通知 CI 失败。助理判断与主人当前关注的仓库相关，主动在 Telegram 提醒；若不相关则只记入记忆，不打扰。
4. **能力扩展**：主人在控制台粘贴一个 MCP 服务器配置（如 `uvx mcp-server-fetch`），10 秒后助理就能使用它；拷贝一个 `skills/pdf/` 目录进数据卷，助理在下一回合就能看到该 Skill。
5. **审批**：助理想执行 `rm -rf` 级别的操作或发送邮件给第三方。该工具被策略标为 `ask`，助理向主人发出审批请求；主人的"同意"回复作为 L1 事件回流，工具继续执行。

## 成功标准（v1.0）

- 在一台 1 vCPU / 1 GB 的 VPS 上连续运行 30 天无需人工干预。
- 任意时刻 `docker stop` 再 `docker start`，不丢事件、不丢会话、不重复执行已完成的副作用（幂等接收）。
- 主人消息的端到端首字节延迟（事件入库 → 模型开始输出）P95 ≤ 2s（不含模型思考时间）。
- 新增一个事件源插件（含文档）的工作量 ≤ 半天；接一个现成 MCP 服务器 ≤ 5 分钟。
