# 设计原则

> 状态：Draft · 更新：2026-11-03

这些原则是做取舍时的裁判。每条给出"是什么、为什么、怎么体现"。前五条继承并改写自 Cortico 的 PHILOSOPHY（见 [04-reference-cortico.md](04-reference-cortico.md)），后五条是 Protea 作为"云端个人助理 harness"的自有原则。

## P1 · 内核无语义（Semantics-free Core）

- **是什么**：Core 不解释、不生成任何语义内容。事件的 `text` 由来源提供；系统提示由人格与插件提供；记忆对 Core 不透明。
- **为什么**：语义是最容易过时、最依赖具体模型的部分。把它们放进可替换的层（人格、插件、Skills），Core 才能长期稳定。
- **体现**：Core 的代码中不出现任何面向模型的自然语言；事件渲染只做结构化包装（来源、时间、起源），不做总结或改写。

## P2 · 为未来模型设计（Design for future models）

- **是什么**：不把今天模型的局限写进系统的基本语义；为当前模型做的妥协必须是可关闭的回退（fallback）。
- **为什么**：模型每季度换代；回退可以删，内核语义不能改。
- **体现**：抢占、审批、预算是"机械边界"，其余一律通过上下文的语义引导实现；Provider 层隔离具体 API 形态（思考、缓存、回退）。

## P3 · 最小先验干预（Minimal prior intervention）

- **是什么**：基础设施尽量不干涉模型行为；必须干预时（速率限制、安全边界、预算）要**事先声明、事中告知**。
- **体现**：权限策略在系统提示中可见；预算耗尽、抢占发生、工具被取消等都以 `internal` 事件告知模型。

## P4 · 诚实认识论（Honest epistemology）

- **是什么**：系统生成的陈述只能是可验证的事实。禁止把启发式推断包装成事实。
- **体现**：`origin: internal` 的事件只允许 Core 发出，内容仅限状态变化（插件启停、交接发生、预算余量）；外部内容永远标注为 `external` 并视为不可信数据。

## P5 · 默认不作为（Inaction by default）

- **是什么**：助理收到事件后，不行动是合法且常见的结果。是否行动由模型基于语义决定。
- **体现**：回合可以无任何外部输出地结束；L4 环境事件默认 `piggyback`，只在有别的原因唤醒时顺带被看到。

## P6 · 一切皆事件，事件日志是唯一事实源（Event log as source of truth）

- **是什么**：所有输入、所有副作用的意图与结果都是事件；状态是事件的投影。
- **为什么**：重启恢复、回放调试、审计都只需要一份日志。
- **体现**：事件存储 append-only；会话转录 append-only；"撤回"是追加一条撤回记录而非删除。

## P7 · 等级显式、抢占有界（Explicit levels, bounded preemption）

- **是什么**：每个事件源在清单中声明等级与允许的投递模式；抢占只能自高向低；相同等级只能显式中断。
- **为什么**：没有等级，所有事件都"紧急"；没有上限，恶意或失控插件可以饿死其他来源。
- **体现**：[04-scheduling-and-preemption.md](../10-architecture/04-scheduling-and-preemption.md) 的抢占矩阵与老化规则。

## P8 · 隔离优先于便利（Isolation over convenience）

- **是什么**：插件默认运行在独立进程中，只通过协议与 Core 通信；崩溃、卡死、内存泄漏不影响内核。
- **为什么**：热插拔的本质是"可以随时杀掉再起"，进程是最可靠的边界。
- **体现**：进程外插件协议（JSON-RPC over stdio）是一等公民；进程内插件仅限内核自带、经审计的来源。

## P9 · 可重启是常态（Restart is normal）

- **是什么**：任何组件随时可能被重启（升级、崩溃、OOM）。设计必须让重启廉价且无损。
- **体现**：幂等事件接收（来源提供 `dedupeKey`）、工具调用结果缺失时的占位回执、Fork 检查点、启动时的日志修复规则。

## P10 · 主人可见、主人可控（Owner in the loop）

- **是什么**：助理的一切重要行为对主人可见；危险行为可被主人事先限制、事中审批、事后审计。
- **体现**：控制台实时事件流；`ask` 策略的审批走主人常用渠道；每个副作用工具调用都有审计记录。

## 原则冲突时的优先级

安全（P10）> 诚实（P4）> 隔离（P8）> 无语义（P1）> 其余。例如：为了安全可以在系统提示中加入显式限制（牺牲一点 P3），但不能为了便利让插件直接访问记忆目录（违反 P8）。
