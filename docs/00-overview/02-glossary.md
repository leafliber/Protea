# 术语表

> 状态：Draft · 更新：2026-11-03

按主题分组；括号内为代码中使用的英文标识符。中文正文首次出现术语时应链接到这里。

## 运行时与结构

| 术语 | 标识符 | 定义 |
|---|---|---|
| 内核 | `Core` | 无语义的运行时核心：事件存储、调度、会话循环、模型调用、插件宿主。不理解事件内容，不生成语义文本。 |
| 守护进程 | `daemon` | 承载 Core 与控制平面的长驻进程，容器中的 PID 1 子进程。 |
| 运行 | `run` | 守护进程的一次启动到停止。每次运行有 `runId`，日志与转录按运行归档。 |
| 助理档案 | `AssistantProfile` | 一次部署的"装配清单"：人格 + 启用的插件集合 + 配置。相当于 Cortico 的 Bot。 |
| 人格 | `Persona` | 定义助理身份、行为准则、记忆布局与上下文合成规则的一组文件与钩子。 |
| 记忆 | `Memory` | 人格的持久化内部状态（文件目录），对 Core 不透明。 |
| 控制平面 | `ControlPlane` | HTTP API + WebSocket + Web 控制台 + CLI，用于运维与观察。 |
| 对话平台 | `chat platform` | 声明了对话能力的连接器（内置 `webchat`，还有 `telegram`）。主人的消息是 `chat.message` 事件，回复用 `chat_send`，必须指定平台。 |
| 运行流 | `run stream` | 控制台上的完整过程时间线：事件、用户输入、上下文摘要、思考、正文、工具调用、发出的消息、调度动作。 |
| 数据卷 | `/data` | 所有持久状态所在目录（配置、事件库、会话、记忆、插件、Skills）。 |

## 事件

| 术语 | 标识符 | 定义 |
|---|---|---|
| 事件 | `Event` / `EventEnvelope` | 世界发生变化的一条记录。由事件源产生，带游标、来源、起源、等级、投递模式与文本。 |
| 游标 | `cursor` | 事件在存储中的单调递增序号；全局唯一、持久化后分配。 |
| 来源 | `source` | 产生事件的插件 ID（如 `telegram`、`cron`）。 |
| 起源 | `origin` | `external`（来自外部世界，不可信）或 `internal`（内核可验证的内部通知）。 |
| 处理等级 | `level` | L0–L4 的优先级，数字越小越紧急。决定批处理窗口、可用投递模式、抢占能力与预算池。 |
| 投递模式 | `trigger` | 事件进入会话的方式：`debounce` / `flush` / `preempt` / `interrupt` / `piggyback` / `store` 。 |
| 批 | `batch` | 一次投递给主会话的一组事件；一个批触发一个或多个回合。 |
| 投递 | `delivery` | 事件被渲染进会话上下文的动作；每个事件有且仅有一次成功投递记录（或撤回/丢弃记录）。 |
| 撤回 | `withdraw` | 事件在投递前被来源收回（例如消息被删除）。 |
| 升级 | `promote` | 把一个未投递事件的投递模式提升（如 debounce → flush）。 |

## 调度与会话

| 术语 | 标识符 | 定义 |
|---|---|---|
| 调度器 | `Scheduler` | 根据等级与投递模式决定事件何时、以何种方式进入哪个会话，并执行抢占。 |
| 主会话 | `MainSession` | 唯一的、常驻的、接收事件的会话。串行处理批。 |
| Fork 会话 | `Fork` | 由主会话或调度器派生的独立工具循环，用于后台长任务；有自己的转录与等级。 |
| 回合 | `turn` | 一次模型调用及其引发的全部工具调用，直到模型结束或被取消。 |
| 回合边界 | `turn boundary` | 新事件可以进入上下文的时刻：所有工具返回后、或模型调用被取消后。 |
| 运行阶段 | `RunPhase` | 主循环状态：`idle` / `delivering` / `model` / `tools` / `backoff` / `handoff`。 |
| 抢占 | `preempt` | 取消尚未产生外部输出的模型调用，用新事件重新请求。 |
| 中断 | `interrupt` | 取消当前回合（即使已有外部输出），停止可中断工具，跳过未开始的工具。 |
| 交接 / 压缩 | `handoff` | 把较早的对话压成一份笔记，带着白板和最近的消息开始新转录；常态在空闲时发生（闲时压缩），接近容量上限时是兜底。 |
| 白板 | `board` | 目标、待办、注意事项的结构化列表，由 `board` 工具更新，不进系统前缀。 |
| 原文层 | `raw layer` | 日志、压缩笔记、对话归档、转录：保留供审查，默认不被检索召回。 |
| 梦境 | `dream` | 每日在空闲时运行的后台 Fork，把原文层折叠进笔记并维护索引。 |
| 检查点 | `checkpoint` | Fork 被抢占/暂停时持久化的恢复点。 |

## 能力层

| 术语 | 标识符 | 定义 |
|---|---|---|
| 插件 | `Plugin` | 可热插拔的扩展单元。种类：`source` / `connector` / `tool` / `provider` / `mcp` / `skill`。 |
| 事件源 | `Source` | 向内核推送事件的插件（入站）。 |
| 出口 | `Sink` | 把助理的动作送回外部世界的能力（出站），表现为工具。 |
| 连接器 | `Connector` | 同时是事件源与出口的插件（如 Telegram）。 |
| 工具 | `Tool` | 模型可调用的函数，有名称、描述、JSON Schema 输入与处理器。 |
| 回执 | `receipt` | 工具调用的结果记录（文本 + 附件 + 是否失败 + 是否部分完成）。 |
| 环境提示 | `envPrompt` | 插件提供的、描述"何时/如何使用本插件"的系统提示片段。 |
| MCP 服务器 | `McpServer` | 通过 Model Context Protocol 提供工具/资源/提示词的外部进程或服务。 |
| Skill | `Skill` | 一个含 `SKILL.md` 的目录，按 Agent Skills 规范提供可按需加载的指令与资源。 |
| 模型提供方 | `Provider` | 对接某家模型 API 的适配器（Anthropic 为默认实现）。 |
| 宿主 | `PluginHost` | Core 提供给插件的 API 面：推事件、读配置、取秘密、记日志、上报用量。 |

## 安全与运维

| 术语 | 标识符 | 定义 |
|---|---|---|
| 主人 | `owner` | 唯一有权指挥助理的人；由各渠道的身份映射到同一 owner。 |
| 权限策略 | `PermissionPolicy` | 工具级别的 `allow` / `ask` / `deny` 规则集。 |
| 审批 | `approval` | 策略为 `ask` 的工具调用等待主人决定的记录；决定以 L1 事件回流。 |
| 时限授权 | `grant` | 批准时附带的时限：到期前同一组工具的 `ask` 调用直接放行，照常审计。 |
| 权限模式 | `PermissionMode` | 策略为 `ask` 的调用由谁放行：`ask`（主人）、`auto`（判断模型，没放行的转给主人）、`bypass`（直接执行，必须带时限）、`locked`（一律不执行）。 |
| 判断模型 | `judge` | auto 模式下审核单次工具调用的模型角色，默认用主模型；只能看到主人的话和工具调用，看不到回执。 |
| 钉住 | `pinned` | 主人在 `permissions.tools` 里显式写的 `ask`：auto 和 bypass 下也要主人点头。 |
| 沙箱 | `sandbox` | 运行助理 shell 的独立容器；没有 `/data`，经 unix socket 由 `shell` 插件调用。 |
| 图片引用 | `blob` | 内容寻址存储的图片，句柄 `blob:<sha256>`；转录里只有句柄，字节只在发给模型的请求里。 |
| 预算 | `budget` | 按等级与时间窗口划分的 token / 费用上限。 |
| 热更新 | `hot` | 配置项变更无需重启即生效；标记 `x-hot: false` 的项需要重建相关组件。 |
